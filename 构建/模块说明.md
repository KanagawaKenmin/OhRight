# 构建与验证边界

负责源码交付核验、工程生成、模拟器测试和无签名设备包；不属于 App 的四层运行时代码。

| 文件 | 职责 | 何时读取 |
|---|---|---|
| [准备工程.sh](准备工程.sh) | 锁定工具链与生成工程 | 工程准备失败时 |
| [验证工程.sh](验证工程.sh) | 限时执行源码检查、核心、模拟器编译/启动/单元/UI | 云构建阶段失败时 |
| [模拟器准备.py](模拟器准备.py) | 按 SDK 主次版本匹配运行时、创建专用设备、启动就绪和一次重试 | BackBoard/启动超时时 |
| [检查源码版本.py](检查源码版本.py) | 核对项目版本和交付文件哈希 | 旧源码、混合上传或漏文件时 |
| 源码清单.json | 当前交付文件的规范化 SHA-256；只由本地交付步骤重建 | 核验上传完整性时 |
| [打包个人版.sh](打包个人版.sh) | 未签名设备 IPA、平台/版本/哈希信息 | 设备产物问题时 |
| [静态检查.cjs](静态检查.cjs) | Windows Swift/Bash 语法和配置检查 | 无 Apple SDK 时 |

源码清单不含文档、用户资料或构建产物；文本规范化 BOM/CRLF，防止 Windows 与 Git 换行差异误报。源码变更后由交付者运行 `python3 构建/检查源码版本.py --write-manifest`，再运行无参数命令核验；CI 只核验，不能自动重建清单掩盖上传不完整。

模拟器使用本次创建的 `OhRight-CI-*` 设备与当前 SDK 对应运行时，设备 UUID 贯穿编译/启动/测试。启动最多两次，每次仍必须通过 bootstatus；不得用 Booted 状态冒充就绪或跳过测试。重试只重启专用设备，不清除其他模拟器。诊断和选择信息作为 JSON/日志归档。

构建编排用例：[测试/构建模块说明](../测试/构建/模块说明.md)。2026-10-21 Windows 下 11 项通过；真实 SDK/启动恢复待 Codemagic 执行。
