# 构建与验证边界

负责源码交付核验、工程生成、模拟器测试和无签名设备包；不属于 App 的四层运行时代码。

| 文件 | 职责 | 何时读取 |
|---|---|---|
| [准备工程.sh](准备工程.sh) | 锁定工具链与生成工程 | 工程准备失败时 |
| [验证工程.sh](验证工程.sh) | 限时执行源码检查、核心、模拟器编译/启动/单元/UI | 云构建阶段失败时 |
| [模拟器准备.py](模拟器准备.py) | 按 SDK 主次版本匹配运行时、创建专用设备、启动就绪和一次重试 | BackBoard/启动超时时 |
| [检查源码版本.py](检查源码版本.py) | 核对项目版本和交付文件哈希 | 旧源码、混合上传或漏文件时 |
| [失败摘要.py](失败摘要.py) | 本次日志清单、首个错误、断言/超时分类和 JSON 阶段结果 | 日志末尾或失败归因时 |
| [收集崩溃报告.py](收集崩溃报告.py) | 限时尽力复制近期报告，单文件失败不终止清理 | 清理或诊断失败时 |
| 源码清单.json | 当前交付文件的规范化 SHA-256；只由本地交付步骤重建 | 核验上传完整性时 |
| [打包个人版.sh](打包个人版.sh) | 未签名设备 IPA、平台/版本/哈希信息 | 设备产物问题时 |
| [静态检查.cjs](静态检查.cjs) | Windows Swift/Bash 语法和配置检查 | 无 Apple SDK 时 |
| [检查手势接口.cjs](检查手势接口.cjs) | 拦截 UIKit 桥接对象误传 simultaneousGesture / highPriorityGesture 的直接调用 | 首页类型检查失败时 |

源码清单不含文档、用户资料或构建产物；文本规范化 BOM/CRLF，防止 Windows 与 Git 换行差异误报。源码变更后由交付者运行 `python3 构建/检查源码版本.py --write-manifest`，再运行无参数命令核验；CI 只核验，不能自动重建清单掩盖上传不完整。

模拟器使用本次创建的 `OhRight-CI-*` 设备与当前 SDK 对应运行时，设备 UUID 贯穿编译/启动/测试。启动最多两次，每次仍必须通过 bootstatus；不得用 Booted 状态冒充就绪或跳过测试。重试只重启专用设备，不清除其他模拟器。诊断和选择信息作为 JSON/日志归档。

构建编排用例：[测试/构建模块说明](../测试/构建/模块说明.md)。2026-10-24 Windows 下 27 项通过；此前 16 项已在云端通过，新增诊断与预算用例尚待云端运行。

2026-10-26 最新反馈中五项 UI 四项通过，声音用例失败；UI 阶段约 209 秒自然退出 65，未超时。用户要求移除声音功能和测试，现只运行其余四项 UI。UI 上限保持 300 秒，单项原默认 120 秒、最高 180 秒；主验证全局截止 25 分钟及独立限时诊断保留。verify 上限 30 分钟，个人打包 45 分钟。不得为应对超时擅自提高这些上限。

`verification-current-logs.txt` 每次验证开始重置，只登记本次已启动阶段；摘要跳过旧日志和已通过阶段的恢复性错误。退出后先尽力诊断/关闭专用设备，再输出首个错误、失败用例及 `verification-result.json`；断言与后续超时可同时保留，原退出码不被诊断覆盖。真实旧日志已本地回放核对。

声音专用 `diagnose-settings` 工作流、`--settings-ui-only` 过滤及分支均已删除。验证入口无参数，完整运行当前所有 UI；个人打包保持先验证再打包，静态检查核对该约束。源码核验输出清单指纹和 CI 提交号；未知提交明确为空。

用户日常安装直接运行一次 `package-personal`，内部完成验证后再打包；无需先另跑 verify，避免重复消耗额度。
