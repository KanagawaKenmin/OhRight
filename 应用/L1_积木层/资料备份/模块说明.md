# 资料备份

## 模块职责

完整 ZIP 备份、旧 JSON 兼容、可读 Markdown 与本地附件文件。所属层级：L1。

## 文件导航

| 文件 | 职责 | 何时读取 |
|---|---|---|
| [备份编解码.swift](备份编解码.swift) | BackupEnvelope / BackupCodec，版本、UUID、内容校验 | 修改对应行为时 |
| [备份日期编码.swift](备份日期编码.swift) | 新日期标记与旧毫秒备份的兼容分流 | 日期往返/恢复兼容时 |
| [完整备份容器.swift](完整备份容器.swift) | manifest、附件哈希、含草稿整库往返 | 备份导入导出时 |
| [受限ZIP容器.swift](受限ZIP容器.swift) | 无压缩 ZIP、目录/路径/大小/CRC 校验 | 容器格式和损坏拒绝时 |
| [文件摘要.swift](文件摘要.swift) | SHA-256、CRC32；Apple 使用 CryptoKit | 完整性检查时 |
| [附件仓库.swift](附件仓库.swift) | 原子文件写入、同名冲突及引用清理 | 本地图片持久化时 |

## 接口与流程

依赖 L0；不调用 L2/L3。 对外能力见各文件头与类型/函数声明。当前只实现本地个人试用；云端相关协议另在文档约定，不建立网络占位实现。

保存由 AppModel 显式协调；规则值不可直接触碰数据库。通知由系统适配器提交，UI 不能以投递成功冒充已被用户看见。

## 依赖边界与验证

完整备份 v2 包含 manifest.json 和 attachments/*.png；可读 ZIP 包含便条.md 与图片。原 v1 JSON 仍可导入，带图片路径却没有文件的 JSON 会被拒绝。ZIP 只接受本应用的无压缩、无注释单卷格式；上限 250 MB、10,000 文件，manifest 上限 50 MB。路径不会直接解压到磁盘。

附件先写临时文件再移动；只有文件落盘后 UI 才提交引用。草稿、回收站、记录及上一版引用参与清理；安全快照自身包含图片。

2026-10-24 修复日期精度：新 v2 清单标记 `dateEncoding=referenceSeconds`，使用 Date 原生编码，避免纪元平移及乘除 1000 导致浮点变化。v1 和无标记早期 v2 仍按 Unix 毫秒读取；未知标记拒绝。原完整草稿相等断言保留，新增逐位日期及旧格式兼容测试。第 8 次云端核心编译成功，旧编码的含图备份测试失败；修复后待重跑，见[实施记录](../../../文档/体验改版实施_0.3.md)。
