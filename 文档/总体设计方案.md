# 哦对了 · 总体设计方案

版本：0.2。更新：2026-10-15（Asia/Tokyo）。定位：免费 Apple ID 自签名的个人 iPhone 试用版。用户已授权按本版开发，本地源码与构建流程已实现，编译及真机验收待完成。

## 1. 产品主张

**把还没想完的念头留下来，把已经决定的事情向前推一点。**

“哦对了”保留想法重新浮现的瞬间。琐事允许不完整，计划帮助迈出下一小步；先验证自己是否愿意日常使用，再决定是否投入服务器或公开分发。

## 2. 已确认范围与本次修正

| 项目 | 当前决定 |
|---|---|
| 使用对象与设备 | 自己使用，iPhone 17 原生 App |
| 开发条件 | Windows，无实体 Mac；需要编译时使用云端 macOS |
| 安装 | 免费 Apple ID 自签名，先试效果 |
| 提醒方式 | 默认本地模式；云端模式只预留接口与接入说明 |
| 本地算法 | 本机按规则筛选琐事、随机洗牌，再随机安排提醒时间 |
| 时间选择 | 避开每日免打扰时间带 / 全天随机；计划仍固定时间摘要 |
| 应用启动 | 用户接受经常打开应用；启动补排是正常使用方式 |
| 云端与上架 | 排程、信息同步、推送等只留接口；不实现服务器、账号体系或商店分发 |
| 当前实施 | 本地 App、规则测试与构建配置已写入；服务器及云接口继续仅留契约 |

本版替代 0.1 中付费开发者会员、TestFlight 安装和较长无人值守排程的默认方案，不再将它们作为个人试用的前提。

## 3. 总体架构

**SwiftUI + SwiftData + 本地规则排程 + iOS 本地通知。编译与签名分开：云端生成设备版未签名 IPA，Windows 用免费 Apple ID 重签并安装。**

| 部分 | 试用阶段做什么 |
|---|---|
| 界面 | 琐事与计划两个模式，共用首页骨架 |
| 资料 | 单设备本地保存；保留稳定 UUID、资料版本和导出能力 |
| 提醒策略 | 本地策略真实可用；云端策略通过能力开关保留接入点 |
| 通知投递 | 接入 iOS 本地通知；未来 APNs 适配器仅写契约 |
| 业务网络 | 不建立连接，不上传事项，不需要登录 |
| 构建 | 云端 Mac 只编译和测试，不接收 Apple ID 或用户资料 |
| 安装 | 优先 Windows Sideloadly + USB + 免费 Apple ID；真机验证后固定流程 |
| 后续扩展 | 只定义必要协议、数据格式与使用顺序，不建设闲置基础设施 |

本地通知由系统处理已提交请求；不需要持续运行的后台计时器。[Apple 本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)。

## 4. 两条核心使用路径

**琐事：记一句 → 逐渐补充 → 随机重见 → 完成或转成计划。**

例如“想把阳台弄舒服一点”，之后补充“先换个灯”。不要求创建时就提供目标、期限和完整步骤。

**计划：确定截止 → 写下一小步 → 记录进展 → 完成。**

例如“10 月 30 日交材料”，下一步是“找去年版本”。固定摘要展示近期截止与可执行动作，不靠反复催促或惩罚推进。

## 5. 两种开关不要混淆

- 首页的**琐事 / 计划**决定内容和视觉。
- 设置中的**提醒方式：本地 / 云端**决定排程与投递实现。当前只有本地可用；云端标注“尚未接入”，禁用或隐藏其操作，不做假切换。
- 本地提醒里的**避开免打扰 / 全天随机**决定时间规则。
- 未来接入云端后允许切回本地，资料仍能离线读写；具体交接顺序见接口文档。

## 6. 本地试用版范围

| 保留的核心功能 | 当前暂不开发 |
|---|---|
| 一句话记录、草稿、补充时间线 | 自动空闲识别、日历或位置授权 |
| 计划截止、下一步、进度与检查项 | AI 拆解、重复计划、附件与协作 |
| 完成、归档、转计划、搜索与恢复 | 账号登录、多租户、订阅、商业统计 |
| 简单随机洗牌、频率与免打扰 | 学习型推荐、后台常驻与自动续排服务 |
| 每日固定摘要、可选期限提醒 | 云排程、APNs 实际注册和推送 |
| 通知跳转、稍后、完成后取消提醒 | 多设备同步、云数据库、后台管理 |
| 本地备份导出与恢复 | TestFlight / App Store 发布流水线 |
| 双模式视觉、深浅色与基本无障碍 | 面向公众的审核、运营和商店素材 |

保留本地保存与备份的基本可靠性，它们直接保护试用内容；不提前建设面向公众的账户安全、分布式同步和线上运维系统。

## 7. 简化后的排程规则

1. 本地筛选活动、允许提醒的琐事，按种子随机洗牌，按顺序取出。保留次数上限与基本冷却，不做行为画像或复杂权重。
2. 默认每天至多 1 条，可选 0 / 1 / 2 条。时间从免打扰之外或全天抽取；没有合适事项就不发。
3. 计划摘要默认每日 20:30，可修改；无活动计划时不发空摘要。
4. **每次启动、回到前台或修改事项后，补齐未来 3 天。** 保留仍有效的时刻，不每次打开都重新打乱已经提交的通知。
5. 不开发后台刷新，也不额外发“请打开续排”的提醒。设置页显示“已安排到……”即可；用户接受通过打开 App 补排。
6. 系统最终呈现仍受通知权限与专注模式影响。队列用尽就等下次打开，不为此接入服务器。

3 天是试用设计参数，不是 iOS 的平台上限；以后可按使用反馈调整。

## 8. 视觉方向

首页维持顶部名称与更多菜单、左右模式开关、内容卡片、底部一个主按钮。

- 琐事：暖白、淡青与浅紫、大圆角、低幅流动装饰，文字和点击区域稳定。
- 计划：网格对齐、小圆角或直角、深色标题、少量朱红强调，突出截止与下一步。
- “我现在有空”保留为轻量主动抽取入口，不增加一套复杂导航。
- 深浅色、大字体和减少动态效果保留；系统通知遵循 iOS 样式。

详见[产品与交互设计](产品与交互设计.md)。

## 9. 免费自签名与试用维护

路径：**私有代码仓库 → 云端 macOS 编译设备版 IPA → 下载到 Windows → Sideloadly 免费 Apple ID 签名 → iPhone。**

免费账号的安装描述文件通常有效 7 天，需要续签；这与 App 内“打开后补排”不同。打开 App 不能延长签名。免费个人配置也存在同时安装数量限制。[Apple 免费账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)、[Sideloadly 官方说明](https://sideloadly.io/)。

建议首次用 USB，之后每 5–6 天续签一次；不升级代码时可重签同一个 IPA。保持 Apple ID 与有效 Bundle ID，先验证覆盖安装保留资料。云构建优先使用免费额度，额度不足时停止，不默认开通付费。

具体步骤、未签名设备构建与模拟器的区别见[部署与维护方案](部署与维护方案.md)。

## 10. 交接与后续扩展

执行顺序：最小 App 自签名装机与通知验证 → 本地资料与双模式界面 → 本地提醒闭环 → 备份与个人试用。预计规模以验证结果滚动评估，不再将公开分发准备纳入交付周期。

[云端接口与交接约定](云端接口与交接约定.md)说明排程、资料交换、设备推送、能力与模式切换的输入输出、调用顺序和失败行为。**预留接口不代表现在实现云客户端、网络请求或服务器。** 上架属于未来构建与分发配置，不给业务层添加没有实际用途的“上架服务”。

用户后续已明确授权本地开发，实施状态见[开发验证记录](开发验证记录.md)；云端与公开分发范围仍然暂缓。
