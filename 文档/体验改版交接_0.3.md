# 哦对了 0.3 体验改版交接

日期：2026-10-21。状态：方案待用户审阅，未修改应用代码。由当前对话分析，用户手动移交另一模型实施。后文具体控件、限额及分期属于工程建议，不冒充已获批准的细节。

执行状态补记（2026-10-21）：用户已在执行聊天授权按本方案开发，四阶段源码已实施；构建与真机退出条件仍待验证。当前事实见[0.3 实施记录](体验改版实施_0.3.md)，下文保留原交接时的方案描述。

## 目标与范围

让首次提醒、查找旧记录和常用操作自然可见。保留琐事／计划双模式和流动／几何视觉；设置使用克制的系统分组列表，不混入首页装饰。继续个人免费签名、本地存储与本地通知；云端仅留契约，正常界面隐藏不可用选项。

本轮依据：用户两张真机截图及文字反馈。截图证明已进入实际使用阶段，不代表锁屏通知、完整备份恢复或覆盖续签已经验收。

## 反馈与现状核对

| 反馈 | 当前源码事实 | 处理 |
|---|---|---|
| 先点测试通知才知道如何授权 | SettingsView 保存已启用偏好时也会调用 enableNotifications，但默认 enabled=false，流程隐蔽 | 首页首次出现时请求；独立处理授权与提醒开关 |
| 提醒与设置太像开发者工具 | 同页包含模式、队列覆盖、重新安排、诊断与用户偏好 | 设置分级；技术状态移入故障排查 |

| 琐事应能成为计划的前一步 | 同一 Item 已支持 kind 转换、保留 UUID；入口在详情更多菜单 | 提升“转为计划”入口，复用现有流程 |

| 无声弹窗提醒 | 当前默认 soundEnabled=false，通知 sound=nil | 保持无声横幅，修复授权和排程入口 |

## A. 首次启动与通知

1. 主界面完成加载、应用处于前台且没有其他系统弹窗时，读取系统授权状态。仅 notDetermined 自动发起一次标准通知授权请求；无额外教程或二次确认。
2. 加入会话内请求互斥，防止首页重建、前台事件和用户点测试同时弹出请求。拒绝后不重复请求；显示“通知未开启”及“前往设置”。
3. 新用户同意后自动开启提醒并补排，默认无声、每日最多一条琐事、20:30 计划回顾。空库不制造演示提醒；新事项冷却规则不变。
4. 拆开现有 enableNotifications 的“请求权限”和“打开总开关”：测试通知只做测试，不顺便改变长期偏好；读取系统权限也不能打开用户主动关闭的提醒。
5. 升级处理：未申请权限的旧安装也执行一次请求。由于旧版 enabled=false 无法区分默认关闭与主动关闭，旧库保持原偏好；授权成功且总开关关闭时提供一次“开启提醒”操作，不静默覆盖。
6. 新增持久化引导版本及用户选择标记；旧库缺字段按兼容值读取。系统权限始终重新查询，不从备份恢复授权状态。拒绝不阻断记录功能。
7. 返回前台刷新权限和队列；在系统设置中重新允许通知后，仅当 App 提醒开关已开才补排。
8. 标准授权可请求 alert、sound，但默认通知 content.sound=nil；开启声音后才附默认声音。前台展示由通知代理遵守同一偏好。无声不等于 provisional，也不承诺绕过系统专注模式或强制横幅样式。
9. “发送测试通知”保留在帮助页，提示“两分钟后发送，请锁屏等待。”重复点击保持稳定 ID，不重复堆积。权限拒绝时先引导设置，不能显示发送成功。

## B. 导航与设置

首页保留当前分段开关、主按钮和更多按钮；更多菜单按顺序为“搜索”“历史记录”“设置”，不用新增底部导航栏。

```text
搜索：默认所有未删除事项，可筛琐事／计划及状态
历史记录：已完成 | 已归档，支持页内搜索
设置
  通知与提醒                         开启 / 已暂停 / 通知未开启
  外观                               跟随系统
  备份与恢复
  回收站
  帮助与关于
    提醒帮助
    发送测试通知
    故障排查                        队列、重新安排、报告
    版本
```

历史记录与搜索可共用查询服务，但使用不同标题、初始过滤和路由；历史的“全部”只能指已完成加已归档，不能夹带进行中。回收站独立入口；保留恢复与永久删除确认。

“通知与提醒”二级页：

| 分组 | 控件 | 细节 |
|---|---|---|
| 提醒 | 允许提醒 | App 总开关；关闭后保留子偏好但暂停安排 |
| 琐事 | 每天提醒：关闭／最多 1 次／最多 2 次 | 不把“最多”显示成必达数量 |
| 计划 | 每日回顾、回顾时间 | 时间仅开启时出现；独立期限提醒仍在计划编辑里 |
| 时间 | 免打扰时段 | 可添加多段；关闭后允许全天安排 |
| 通知 | 显示内容、声音 | 声音默认关；内容开关沿用现有隐私语义 |
| 系统 | iPhone 通知设置 | 只有系统禁用或横幅关闭时显示对应状态提示 |

沿用当前 timePolicy：免打扰时段开启对应 avoidQuiet，关闭对应 allDay。它仍作用于所有提醒，不能悄悄改成只影响琐事。全天随机包括夜间。

设置即时保存，不再设置整页“保存”按钮。普通开关一次事务提交；时间段编辑在子页用“完成”一次提交，取消不改变原值。时间重叠可合并；跨午夜需显示为“23:00–次日 09:00”。

如免打扰覆盖回顾时间，提交前在该子页显示“回顾时间在免打扰时段内，请调整时间。”并保留待修改值；不能自动移动回顾时间。保存失败回滚控件，给可理解提示。快速连续操作沿用版本核对及串行重排，不覆盖另一项刚保存的设置。

正常页只显示能帮助用户采取行动的异常。排程容量不足可显示“部分提醒暂未安排”并链接帮助；请求 ID、计算覆盖、原始错误只进入故障排查。保留 local/cloud 字段和能力协议，隐藏当前不可用模式选择。

## C. 文案规范与替换

主功能名称用常见名词；按钮用明确动作。品牌语气可留在首页空状态，设置、错误、权限和删除确认不写隐喻。没有额外信息的说明删除，条件性说明只在相关状态出现。

| 原文 | 新文案／处理 |
|---|---|
| 提醒与设置 | 设置 |
| 搜索、完成与归档／之前的念头 | 搜索／历史记录，按实际页面分别命名 |
| 使用方式：本地／云端尚未接入 | 从正常设置移除 |
| 新记下的念头先放一天，同一条至少隔三天；没有合适的内容就不提醒 | 移到“提醒帮助”：新建或补充后的琐事，24 小时内不会提醒。同一条琐事至少间隔 3 天 |
| 没有进行中的计划时不发空摘要 | 删除常驻说明 |
| 摘要时间需在免打扰之外 | 仅冲突时提示调整 |
| 显示标题和简短摘要 | 显示内容 |
| 锁屏是否显示内容仍遵循系统预览设置 | 正常页删除；帮助中说明锁屏预览可在 iPhone 设置中调整 |
| 系统权限：尚未请求 | 未开启；给“开启通知”操作 |
| 本地计算到／重新检查和安排 | 移入故障排查，后者改为“重新安排提醒” |
| 时间带可以重叠或跨午夜。向左滑动可移除 | 删除常驻说明，用日期样式和删除按钮表达 |
| 任何时刻都可能提醒，包括夜间；系统专注设置仍会生效 | 关闭免打扰后显示“夜间也可能收到提醒。” |
| 留下的痕迹／留下这点想法 | 记录／添加记录 |
| 不打算做了，归档 | 归档 |

必须保留的帮助说明：“提醒会在打开 App 时更新。连续几天未打开，提醒可能暂停。”本地三自然日窗口不变，不能为了文案干净隐瞒使用限制。备份替换资料、永久删除等不可逆操作仍需明确说明后果。

## D. 事项操作

### 转为计划

琐事详情标题区后提供可见的“转为计划”次要按钮；更多菜单可保留相同操作。打开现有计划编辑器，预填原文，补截止日期及下一步。取消不转换，保存才原地更改 kind；原 UUID、时间线、星标、图片和创建时间保留。保存后转到计划详情；撤销旧琐事通知，按计划规则重排。已完成／已归档状态不能因转换被默默恢复，要求先显式“重新开始”。

### 首页手势和长按

- 空白区域左右滑动：向左进入计划，向右返回琐事；不循环。只在明显横向拖动后切换，保留两页滚动位置。
- 不接管卡片、文字编辑、滑杆、系统返回边缘和竖向滚动。优先将手势附到实际空白承载区域，禁止全屏高优先级手势覆盖所有子控件。
- 长按卡片选中并在右侧出现三个圆形按钮：星标、归档、删除；轻触空白退出，选中时不触发导航。窄屏及大字体时操作条放到卡片下方，不遮挡正文。
- 删除先进入回收站，可撤销；归档也可撤销。永久删除仍二次确认。所有按钮有可见标签或辅助标签，点击区域至少 44pt；提供 VoiceOver 自定义操作，不要求用户一定会长按。
- 星标为独立 Bool，不改变事项状态，也不改变随机提醒权重。琐事星标优先、组内沿用更新时间；计划保持日期分组，仅组内星标优先，避免把逾期事项压到后面。新增字段旧库默认 false。

### 预计耗时

用离散滑杆选择“不确定／5 分钟／15 分钟／30 分钟／1 小时／2 小时”，数值实时显示；提供 VoiceOver 调节和点选替代。保持 Int? 分钟存储；旧数据若为非预设值，显示原值，用户未操作时不得自动取整。滑动只改编辑草稿，保存时提交。

### Markdown

建议首版只支持粗体、斜体、行内代码、链接、简单列表。正文及补充记录统一阅读渲染，两种模式一致；标题保持纯文本。编辑页仍编辑 Markdown 原文，可切换预览，无需富文本工具栏。旧内容默认纯文本以避免星号、下划线被误解释；新增内容格式标记需兼容旧库。不会解析的语法按原文显示。

不加载远程图片或 HTML；链接只允许受支持的 http/https，通过用户点击打开。搜索、卡片摘要、通知使用可读纯文本；导出保留源文本。不得依赖 Text(String) 自动提供完整 Markdown，也不能用简单正则删除符号破坏正文。

## E. 图片及备份（独立实施阶段）

图片是持久化功能，必须连同草稿、历史、恢复一起交付，不能只接照片选择器。建议首版在正文／补充记录后显示有序图片组，不做任意文本位置的富文本嵌图；此为待用户审阅的范围取舍。

- L0 定义 Attachment 引用：稳定 ID、相对文件名、类型、尺寸、字节数；Item、ItemEntry 和草稿保存有序引用。修改历史还引用的图片不能立即删除。
- L1 新增附件仓库：App 私有目录保存处理后图片，缩略图单独缓存，不将图片二进制塞进 SwiftData 快照或 UserDefaults。
- L3 用系统照片选择器按需导入静态图片。建议长边最多 2048px、处理后每张不超过 5MB、每事项含记录最多 20 张；这些是待确认默认值。修正方向、保留透明度，去除不需要的定位元数据；不自动申请整库照片权限。
- 图片先写临时区，再完成文件落盘与元数据事务；失败不得留下指向不存在文件的引用。中断后的孤立文件通过引用扫描清理，扫描包含草稿、回收站和历史修订引用。
- 删除事项进回收站时保留附件；永久删除或到期清理后只清理无其他引用的文件。关闭编辑器保留含图草稿。
- 备份格式升级为包含 manifest.json 和附件的 ZIP；原 JSON 无图片旧备份继续支持导入，不能把仅含路径的 JSON 称为完整备份。可读导出增加 Markdown 与图片目录的 ZIP。
- 导入先在暂存区校验路径穿越、重复 ID、体积上限、清单及文件哈希，完成安全快照后事务切换；损坏／缺图时不替换当前资料。历史文本格式、星标和图片均完整往返。
- schemaVersion 升级并实现明确迁移；Swift 的声明默认值不等于合成 Codable 会给旧数据缺字段自动补值。必须测试旧版原始 JSON 样本，而非只测试新对象往返。

## F. 交接定位与实施次序

先读项目导航和各模块说明。部分模块说明仍有过期的“待云端验证”字样；0.2 已通过的依据以《开发验证记录》及 build/codemagic 核验产物为准。

| 阶段 | 涉及入口 | 退出条件 |
|---|---|---|
| 1 通知与设置 | 应用装配.swift、跨模块流程/提醒协调.swift、系统接入/本地通知投递.swift、界面/设置、首页.swift、资料浏览页.swift | 首次授权、拒绝／恢复、即时设置、历史分流通过 |
| 2 常用交互 | 事项详情页.swift、事项编辑页.swift、首页.swift、事项卡片.swift、L2 记录模块、L0 Item | 转计划、滑动、长按、星标和耗时完成；旧数据可读 |
| 3 Markdown | 正文／记录共用渲染、L0 格式标记、搜索及导出 | 原文可回编，纯文本兼容，通知无语法残留 |
| 4 图片闭环 | L0 引用和草稿、L1 附件及备份、L3 导入恢复协调 | 完整备份往返、中断恢复、回收站引用安全通过 |

每阶段可独立验证，不以隐藏测试、跳过失败或重置用户数据库换取通过。继续四层边界，L0／L2 不引入 SwiftUI、PhotosUI；通知及文件协调在 L3，基础附件 I/O 在 L1。文档与功能状态必须区分“已实现”“云端已验证”“真机已验证”。

## G. 验收清单

- 全新安装前台只弹一次通知授权；同意即启用，拒绝仍可记录，再开 App 不反复弹窗。
- 升级旧库保留关闭偏好、事项 ID、状态、时间线、草稿、截止时区；权限未知和已授权两条升级路径分别验收。
- 测试通知不修改总开关，关闭声音时前台／锁屏通知均无声；系统专注／横幅关闭的影响与 UI 状态一致。
- 设置改完退出、杀进程重开值仍一致；存储失败恢复原值；跨午夜免打扰和回顾冲突有明确处理。
- 正常设置看不到云端占位、队列编号、计算截止或原始错误；历史页只显示已完成／已归档，搜索不遗漏进行中事项。
- 转计划保留完整资料、取消无变更；旧琐事通知撤销，点击保留的通知能正确路由。
- 长按不误开详情；归档／删除可撤销；空白滑动不抢滚动、编辑和滑杆；VoiceOver 和大字体可完成同样操作。
- Markdown 编辑前后原文一致，旧文本不变义，通知／搜索可读；非法链接和语法回退有测试。
- 图片离线可见，草稿恢复、转计划、删除恢复及含附件备份在新库往返完整；缺图备份和文件写入失败不破坏原库。
- 保留现有核心、存储、界面检查；添加有意义的权限状态协调、旧 schema 迁移、设置事务及附件恢复测试。UI 测试断言实际操作结果，不只检查控件存在。
- 云端 verify 通过再打设备 IPA；用户覆盖安装真机验证。保持同一签名账号和有效 Bundle ID，不要求卸载。实现模型提供改动摘要、迁移说明、IPA 校验值和未验证清单。
