## 0.4.4 卡片点击语义与前置断言

完整用户日志对应 0.4.3（6）、提交 `e29fbf24f185eb5299761792b605d878c19c520a`。构建、48 项 iOS XCTest、18 项 Swift Testing 全通过；UI 双模式/标题横滑用例 33.026 秒通过，侧滑星标/归档/删除撤销 32.901 秒通过。转换与历史分别在场景卡片前置 `exists && hittable` 失败，UI 阶段 145.237 秒自然退出 65。

两次失败的界面树明确显示“从琐事开始”“只在搜索里出现”的事项卡片，frame 均为 (20,238,362,148)，value 为“操作已收起”。场景隔离单元测试也通过，不能把失败归因于记录未生成。就绪断言混入可点击条件，尤其历史测试根本不需要点卡片；此前标题滑动和预算超时问题已越过。

卡片由 onTapGesture 加手工 isButton trait 改为标准 Button，label 内对整张卡片设置命中矩形。保留标识、完整标签、星标值和辅助动作。根手势先判断起点归属：卡片按钮允许横滑、其他原生控件和输入框仍排除；横滑开始取消按钮点击，避免误导航。

场景就绪只判断卡片存在；转换仍调用实际 card.tap，并要求详情的转换按钮存在且可点击，再执行取消/保存与同 ID 验证。快捷动作按钮仍要求可点击，历史仍实际打开历史和搜索核对范围。不是用坐标强点，也没有更改场景创建、延长等待或删除功能断言。

Windows 88 个 Swift 语法、27 项 Python 编排、五项 Node 接口回归通过，ZIP 清单已核验；新 Button 与原生控件分流仍待 iOS UI 复测。145 秒包含两项提前失败，不能视为四项全通过的耗时保证；上限保持 UI 300 秒、verify 30 分钟、打包 45 分钟。

## 0.4.3 在原预算内减少 UI 开销

用户最新片段：UI 阶段达 240 秒时双模式用例启动仅约六秒，最终 300 秒超时，退出 124；该用例仍在第一条文本输入，未到标题横滑。一次输入框定位/快照可耗十余秒，不能据此认定横滑再次失败或正式 App 输入失效，也不能确定宿主慢的唯一原因。

原四项 UI 总共通过编辑器准备五次记录，其中三次只是快捷操作、转换、历史/搜索测试的前置条件。现在三项从已有 Debug 隔离库预置一条经 ItemEditing.create 校验的记录，直接测试目标功能。Bootstrap 必须同时处于 Debug、inMemory 和 --uitest 才调用场景准备；Release 不编译场景代码。未知场景或非空隔离库明确失败，不清库，也不默认回退成成功。

双模式测试不使用预置数据，仍从空库实际打开编辑器、输入、保存、进详情核对标题、返回后标题行横滑、再真实创建 plan。测试文字缩为 Spark / Plan；移除与最终详情断言重复的输入框 value 快照。所有 UI 查询按 TextField / Button / StaticText 类型与标识定位，减少全树 Any 查询。

用例仍四项，星标/归档/删除撤销、转换取消和 ID 保持、历史/搜索范围、双模式录入与横滑均保留。没有关闭 XCTest 等待空闲，没有改用私有 API，没有跳过测试或延长等待/阶段上限。真实键盘录入准备从五轮减为两轮；节省的实际秒数仍待云端测量。

新增两项轻量单元验证场景隔离/有效记录、未知与空场景；Windows 未执行这些 iOS 测试。88 个 Swift 语法、27 项 Python 编排、五项 Node 接口回归通过。UI 300 秒、verify 30 分钟、package-personal 45 分钟保持。

## 0.4.2 标题区域横滑修复

用户本轮日志：UI 四项执行、三项通过，一项 `ModeUITests.testCaptureAndBothModes` 在“标题区域左滑应切换计划”失败；用例合计 179.784 秒，UI 阶段 223.454 秒自然退出 65。此前编译问题已越过；不是 300 秒超时。

代码存在整页画布缺少显式 interaction contentShape 的漏点：背景装饰不参与命中，标题行 Spacer、列表间隙等透明区域不应靠子视图的形状隐式覆盖。现在画布明确使用整矩形触摸范围；卡片/控件仍按原起点边界排除和分流。空白点击识别器只在有展开卡片时启用，普通页面拖动减少候选识别器。

原测试严格比较模式按钮 accessibilityValue 的“已选中”字符串，不能直接证明业务模式状态。测试保留原标题行横滑，不点击分段、不重试；松手等待原四秒内“新计划”主入口出现，再按原路径创建并核对 plan 卡片与详情。失败同时输出主入口文字、计划 isSelected/value 及滑动行位置。

日志片段没有完整界面树或触摸事件，尚不能证明透明命中和状态读取中哪一处是本次唯一原因。上述改动修复明确薄弱点；Windows 86 个 Swift 语法、27 项编排、五项手势接口回归通过，不将这些检查当作真实横滑已通过。

## 0.4.1 首页编译修复

用户反馈 Index 13、提交 `47e3970`，模拟器编译阶段 346.759 秒后退出 65。首错 `ios-build.log:559` 对应 `首页.swift:23`：编译器无法在合理时间内完成 body 的类型检查；测试尚未开始执行。

检查发现 HomeBackgroundTap 遵守 UIGestureRecognizerRepresentable，却被传给要求 SwiftUI.Gesture 的 simultaneousGesture。改为官方支持的 gesture 重载；将首页分成画布、手势、路由、生命周期及弹层构建函数，并给手势工厂明确返回类型，减少单次表达式的泛型求解范围。

新增轻量接口误用检查与五项 Node 回归。用真实上一版源码包回放，准确检出首页第 44 行的误用；修复源码检查为零错误。Windows 86 个 Swift 语法检查、五项专项和 27 项 Python 构建回归通过；这些结果不等于 Xcode 编译已通过。没有提高超时、编译器求解预算或删除 UI 功能。

## 本轮行为

- 首页大标题进入内容区域，整个首页应用内容共享手势入口；标题、说明、分组、左右留白、卡片间隙、空状态与底栏非按钮区域横滑切模式。
- 单笔手势在起点确定卡片或页面归属，约 10pt 后锁定方向。卡片整行命中；控件、文本编辑及最外侧 16pt 系统边缘不接管。屏幕外卡片和按钮不能通过未裁剪矩形阻挡标题滑动。
- 页面与卡片跟手移动，松手吸附或回弹；页面不循环。两列表分别保留滚动位置；切模式只在松手或点击分段入口时提交一次。
- 事项卡片左滑露出横排圆形星标、归档、删除，带文字标签和短动画；行高和文本宽度不变。最多一张展开，竖向滚动、离页和切模式清空；不使用全滑自动删除。
- 星标/生命周期/删除撤销继续调用原业务流程；VoiceOver 直接提供自定义操作，不要求执行自定义横滑。
- 琐事采用青绿渐变，计划采用暖杏渐变；深色有独立背景、卡片与强调色。分段选中项、主入口和状态同步主题。统一卡片圆角，取消 TimelineView 常驻漂浮动画。
- 详情“转为计划”“添加记录 / 保存进展”“做到了 / 重新开始”采用容器等宽、最小高 52–54pt 的按钮。标题降低到可缩放 28pt；状态紧接标题，记录编辑区独立成卡。
- 图片、Markdown、预览共用可换行工具行；新建、事项编辑和记录修正复用，格式/草稿/图片流程沿用原逻辑。

## 文件与边界

主要改动：首页.swift、首页事项操作卡片.swift、事项卡片.swift、视觉样式.swift、事项详情页.swift、事项编辑页.swift、记录编辑页.swift、图片选择编辑.swift、主题色资源、工程版本。

新增共用组件：`首页手势状态.swift`、`首页横向手势.swift`、`首页模式列表.swift`、`首页模式选择.swift`、`整行操作按钮.swift`、`记录格式工具.swift`。均在 L3；不改 L0/L1/L2、备份 schema 或存储路径。

使用 Apple 官方 UIGestureRecognizerRepresentable；方向不成立时在识别开始前失败，只对实际竖向 UIScrollView 建立等待关系。系统管理安装和卸载，没有全局遍历窗口或替换系统手势代理。

最外侧系统边缘保留；App 主交互区按统一坐标命中。真实 iOS 上的斜滑、系统返回、滚动惯性与跨区域起点锁定仍需设备验收，语法检查不能证明这些体验已通过。

声音功能保持移除。Bundle ID `app.ohright.personal`、既有用户资料、草稿、转换身份和通知策略保持；旧声音字段继续仅作资料兼容。原声音测试路径仍用注释占位覆盖，手动上传无需删除旧文件。
