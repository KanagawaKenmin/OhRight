# 云端接口与交接约定

版本 0.2。更新：2026-10-15。用途：供未来执行对话接入云端；**云端部分只保留契约，不开发网络适配器或服务器；本地实际使用的领域协议与适配器已经写入源码**。

## 1. 预留程度

| 类别 | 本地试用实现时需要 | 未来再实现 |
|---|---|---|
| 排程 | 一个统一排程协议 + 本地规则实现 | 云端排程适配器与服务 |
| 信息 | 本地仓库、稳定 UUID、资料版本、导出 | 增量同步、冲突处理、云端删除 |
| 投递 | 本地通知适配器 | APNs 注册、令牌更新、推送 |
| 模式 | local/cloud 标识、能力查询、本地默认 | 云端可用后的真实切换 |
| 用户身份 | 本地不登录；文档定义会话边界 | 身份验证、权限、账号删除 |
| 分发 | PersonalTrial 配置 | Distribution 配置、签名和商店流程 |

首个本地版本只提取本地代码已经用到的协议；其余协议可继续保留在本文件。不要为了“留接口”建立空目录、假服务器、完整 HTTP 客户端、登录页或消息队列。

## 2. 层级与装配位置

- L0：领域快照、规则、提醒计划、模式枚举与必要协议，不依赖某个云厂商。
- L1：本地资料仓库、规则洗牌和时间抽样。
- L2：记录、计划和排程用例，只接收 L0 协议。
- L3：选择策略与投递适配器、将系统通知回调转换为领域操作；未来的网络格式转换也在此。
- 构建配置注入能力，业务代码不判断免费/付费 Apple ID，不直接调用商店发布接口。

主调用链：保存事项 → 获得最新资料版本 → 查询当前模式能力 → 调用排程端口 → 应用通知差量 → 保存结果。首版链路中没有远程调用。

## 3. 共享数据契约

| 类型 | 字段与语义 |
|---|---|
| ReminderMode | local / cloud；个人版默认 local |
| Capabilities | localAvailable、cloudAvailable、contentSyncAvailable、remotePushAvailable、unavailableReason |
| SnapshotEnvelope | contractVersion、snapshotRevision、items、entries、steps、preferences、generatedAt |
| ScheduleContext | mode、modeEpoch、now、deviceTimeZone、windowStart、windowEnd、randomSeed、existingIntents |
| ReminderIntent | intentID、itemIDs、category、fireAt(UTC)、content、sourceRevision |
| ScheduleBatch | contractVersion、batchID、modeEpoch、scope、replaceFrom、validUntil、intents |
| ScheduleReceipt | batchID、acceptedRevision、acceptedIntentIDs、rejectedItems、coverageEnd |
| RemoteSchedulePolicy | policyID、policyRevision、modeEpoch、enabled、effectiveFrom、deviceTimeZone、timePolicy、quietIntervals、ideaDailyLimit、digestLocalTime、contentPreview、sourceRevision |
| PolicyReceipt | policyID、acceptedPolicyRevision、effectiveFrom、acceptedSourceRevision、acknowledgementID；停用时确认停止生成及待发队列取消范围 |
| RemoteChange | entityType、entityID、operation(upsert/delete)、baseServerVersion、clientRevision、payload、mutationID |
| PushRoute | contractVersion、intentID、itemIDs、category、sourceRevision、modeEpoch、expiresAt |
| Session | userID、accessCredential、expiresAt；只由未来身份模块提供 |

UUID、UTC 时间、截止原时区、明确契约版本必须保留。重试沿用 batchID / mutationID，不能每次生成新 ID 导致重复。content 不含账号凭据；PushRoute 只用于定位，不能直接覆盖本地事项。

云端 accountID、push token、serverVersion、同步游标和发件队列不要求现在写进本地数据库。启用同步时再增加 Schema 版本和迁移。当前的本地 revision 只用于本机顺序，不能直接当作多设备全局版本。

## 4. 排程与投递端口

| 端口 / 方法 | 输入 → 输出 | 调用方法与失败规则 |
|---|---|---|
| ReminderPlanner.makePlan | SnapshotEnvelope、ScheduleContext → ReminderIntent[] | 本地实现为规则过滤+洗牌+时间抽样；确定输入可复现 |
| ReminderDelivery.replaceSchedule | ScheduleBatch → ScheduleReceipt | scope 内从 replaceFrom 起替换；本地对 iOS 队列做差量；局部失败必须返回明细 |
| ReminderDelivery.cancelSchedule | scope、modeEpoch、from、operationID → CancelReceipt | 完成/归档/切模式时调用；幂等，只取消己方范围 |
| CapabilityProvider.query | 无 → Capabilities | 个人版云端相关值全部 false，不因联网就变 true |
| ModeCoordinator.requestMode | targetMode → ModeChangeResult | 云端未接入时返回 unavailable，保持 local 与现有队列 |
| CloudScheduleService.setPolicy（仅预留） | Session、RemoteSchedulePolicy、operationID → PolicyReceipt | 信息同步确认后提交规则；服务器以后按规则持续生成提醒，不依赖手机反复上传三日结果 |

CancelReceipt 包含 cancelledScope、effectiveFrom 和 acknowledgementID，未来远端必须能确认停止后续生成。Scope 为类别/设备范围，不能通过任意客户端输入取消其他用户的计划。

替换请求不是删除全部系统通知。必须隔离当前 App 自己的请求，完成一条事项时不能抹掉其他事项的提醒。

未来长时间云端提醒使用 setPolicy 保存规则与最新资料版本，由服务器自行滚动计算；ScheduleBatch 适合本地队列及云端一次性覆盖，不足以单独实现长期云排程。停用时通过 enabled=false 和 effectiveFrom 要求停止未来生成并取消相应待发通知，确认结果参与模式切换；这些均只是契约，不实现定时任务服务。

## 5. 信息同步端口（仅文档预留）

| 方法 | 输入 → 输出 | 未来使用顺序 |
|---|---|---|
| ContentSync.pushChanges | Session、RemoteChange[] → acknowledgedMutationIDs、conflicts、serverCursor | 本地保存后异步调用；服务器确认后才清除待同步记录 |
| ContentSync.pullChanges | Session、cursor → changes、nextCursor | 拉取后先合并本地，再触发摘要与排程更新 |
| ContentSync.deleteRemoteCopy | Session、scope、operationID → deletionReceipt | 用户撤回云服务或删除账号时使用；切回本地不自动等同删除账号 |
| SessionProvider.currentSession | 无 → Session? | 本地模式不用调用；云端需要有效会话，否则返回 authRequired |

首次启用云端时导出完整快照作为基线，再建立持久化增量与删除标记。已删除资料不重新上传。网络失败不阻止本地保存；未来实现需补持久化重试、冲突界面和多设备版本合并，不能只把本地 updatedAt 最大的一条当作普适方案。

这些行为是未来适配器的职责。现在不提前开发 outbox、后台同步、租户数据库、账号登录或线上监控。

## 6. 远程推送端口（仅文档预留）

| 方法 | 输入 → 输出 | 说明 |
|---|---|---|
| PushRegistration.registerDevice | Session、deviceID、APNsToken、environment、preferencesRevision → registrationID | 未来具备推送资格和实际 entitlement 后注册 |
| PushRegistration.updateToken | registrationID、新 token、operationID → receipt | token 变化时更新，不能把 token 当用户身份 |
| PushRegistration.disableDevice | registrationID、operationID → receipt | 停用云模式或注销时停止该设备后续推送 |
| PushRouter.resolve | PushRoute、本地最新资料 → 跳转结果 | 检查过期、模式代次与事项状态，再打开真实内容 |

设备注册必须区分 APNs 环境，凭据放服务器安全配置。当前免费自签名目标不添加推送 entitlement，不调用注册远程通知接口，不伪造 token。即便未来服务器建好，也要重新核对 Apple 账号和签名是否支持需要的能力。[Apple 能力说明](https://developer.apple.com/help/account/reference/supported-capabilities-ios)。

## 7. 模式切换的使用顺序

当前用户界面可显示“本地（使用中）”和“云端（尚未接入）”。云端项不可激活；隐藏其操作也可，但设置结构必须保留提醒方式字段，未来不改动琐事/计划开关。

未来本地转云端：

1. 查询能力、取得会话、用户允许上传所需信息。
2. 同步最新资料并获取服务器确认，选取未来交接时刻 T 与新的 modeEpoch，通过 setPolicy 提交从 T 起生效的规则。
3. 远端只负责 T 之后，保留本地 T 之前的请求；确认远端可接手后取消本地 T 之后的重叠请求。
4. 任一步失败保持原模式；若已经部分修改，完成取消/恢复确认再标为切换成功，不让两端同时拥有同一范围。

未来云端转本地：

1. 通过 setPolicy(enabled=false, effectiveFrom=T) 要求服务器停止 T 之后的生成并取消待发队列，等待明确确认。
2. 本地根据最新资料重建 T 之后的队列，保存模式与代次。
3. 离线无法确认停止时，显示切换待完成并保留原有效模式；不能静默启动重叠本地队列。

已经在途或展示的远程通知不能保证撤回。modeEpoch 可阻止过时操作、错误路由，不保证系统在展示前消除所有重复。APNs collapse ID 也不会去重本地通知。实施云端时必须补齐切换失败、在途通知和交接缺口测试，再开放此开关。

## 8. 错误与本地退路

统一错误建议：unavailable、authRequired、unsupportedContract、revisionConflict、capacityExceeded、networkUnavailable、temporarilyUnavailable。

本地版不创建模拟“云端成功”的返回值。能力不可用就明确保持本地。将来云端暂时离线时资料仍可记录，但不得未经排程归属确认自动改由本地发送同一批通知。

## 9. 未来上架的配置接入点

上架不需要在 App 业务层实现一个 PublishService；它是未来独立构建与分发流程：

- PersonalTrial：本地功能，未签名设备包，本机免费 Apple ID 重签。
- Distribution：未来才配置团队、Bundle ID、签名、推送能力与分发目标。
- BuildCapabilities：供应用查询哪些后端已接入；不从账号价格推断能力。
- 保持导出契约与内容 UUID，未来换 Bundle ID 或签名团队时可导出再导入；不承诺自动继承自签名 App 的数据容器。

公开用户需要的登录、隐私与账号删除、权限隔离、同步和可靠性建设，届时按实际范围设计实现；本轮只保留上述接入点，不创建这些模块。

## 10. 交接执行示例

只做本地试用时：装配 LocalReminderPlanner、LocalNotificationDelivery、LocalRepository；Capabilities 只开启 local；对云端选择返回 unavailable。UI、事项用例和备份通过稳定领域类型工作。

以后接云端时：先实现会话/同步/注册适配器及取消确认，再实现云排程投递；测试通过后打开 cloudAvailable 并开放切换。优先复用领域快照和规则，不复制一套事项模型。

验收边界：目前只检查契约、字段、调用与失败语义能对得上；不以服务器存在、网络连通、APNs 到达或商店可发布为验收条件。
